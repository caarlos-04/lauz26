VTwin — Technical specification

LauzHack 2026 · UBS AI Financial Twin challenge · source: github.com/caarlos-04/lauz26

Product. A financial digital twin you can play. The user builds a profile (interview, or the demo profile Alexia), takes five decisions over ten years, sees month by month what each one does to their money and goals, goes back to any moment to decide something else, and talks to their self of that moment. Every number is computed by a simulation learned from data; the LLM only explains it. Principle: don't predict the future, make it explorable.

Architecture

  • Kotlin Multiplatform + Compose Multiplatform (Kotlin 2.4): one code base for Android, desktop (JVM) and web (Wasm). About 98 % of the Kotlin code is shared (shared/commonMain): model, engine, decision tree, UI, AI agent.
  • Offline pipeline in Python (tools/): learns the model from the data and writes JSON; it is also a second, independent implementation of the engine used as the reference in tests. The app only reads JSON (content/).
  • No backend and no database: the simulation runs on the device; the game is kept in memory.

The twin and the engine

  • State: one FinancialStatement per month: person (age, work, studies, city, household), cash, investments, at most one loan, income, rent, goals, and the changes already decided but not yet due.
  • Engine: a pure function step(statementt) → statementt+1. Each month it applies due changes, grows income, rent and prices, computes every flow by category, pays the loan (annuity), charges interest on negative cash, and sets casht+1 = casht + net. Same inputs and seed always give the same life.

Models and data

  • Monthly flows are learned from the challenge's synthetic dataset (1,200 profiles, 552,295 transactions): for each category a two-part (hurdle) model, "how likely" and "how big", as multiplicative factors fitted by iterative proportional fitting. A statistical test decides which of the person's 15 fields enter each rule (e.g. city and studying for living costs).
  • Ten-year growth comes from Swiss public statistics, as historical means 2000–2025: prices +0.61 %/yr (CPI), wages +1.17 %/yr and rents +1.39 %/yr (BFS indices), plus the BFS 2024 pay curve by age and position.
  • Uncertainty: each uncertain number of a decision (salary, tuition, rent, loan rate…) is a two-piece normal through three quantiles of the data. One "luck" percentile per decision, kept within p5–p95, draws all of them. No Monte Carlo.

Scenarios and counterfactuals

  • Tree of decisions: 5 decisions × 24 months. At each node the user picks one of the actions valid for their state (17 actions; "carry on as you are" is always available). Each decision stores one snapshot and any node can be reopened to branch.
  • Shocks nobody chooses (job loss: 8 % per turn under 25, 4 % from 25 to 62, from Swiss unemployment by age).
  • Luck modes: same luck at the same age in every branch (differences come only from decisions), or independent luck per decision.

Transparency and AI

  • Explore panel: any amount opens into net worth = cash + investments − debt → flows by category → origin, for any month, with each figure labelled dataset, public data, decision or assumption, and a check that the rows add up.
  • Chat with your future self: an agent built with JetBrains Koog 1.3 on OpenAI (gpt-4.1-mini) or Anthropic (claude-haiku-5-5). It receives a briefing with the engine's results only and must copy numbers, never compute or advise. Without an API key it falls back to template answers built from the same numbers.
